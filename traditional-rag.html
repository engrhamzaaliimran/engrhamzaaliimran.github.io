Measure first, then improve the pipeline

Evaluation principle

Retrieval before generation

Ground truth stores exact source evidence, allowing Hit@K, Recall@K, Precision@K and MRR to be measured without depending on the generator.

Design constraint

CPU-conscious

Latency was measured because an improvement that is too expensive on CPU is not automatically the preferred system.

CPU latency trade-off

StageAverage
Nomic query embedding64.32 ms
Dense after embedding1.76 ms
TF-IDF + dense after embedding2.97 ms
TF-IDF + dense + reranker after embedding401.08 ms

Approximate total retrieval: ~66 ms dense, ~67 ms routed dense, ~465 ms reranked.

Selected retrieval design: TF-IDF + dense. The reranker achieved the best aggregate ranking metrics, but policy routing delivered most of the practical benefit for almost no additional CPU latency.

Main conclusion

A simple routing layer beat complexity on the accuracy/speed trade-off.

The project showed that retrieval should be diagnosed before adding heavier components. TF-IDF policy routing substantially cleaned the search space at negligible cost; cross-encoder reranking improved ranking further but added ~400 ms CPU latency. The resulting classical pipeline is preserved as the baseline for the GraphRAG study.
