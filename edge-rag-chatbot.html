Edge RAG · In-browser portfolio chatbot

A local RAG chatbot for my research website.

I built a Retrieval-Augmented Generation chatbot for this portfolio so visitors can ask questions about my research, publications, technical projects, experience, and academic activities without manually navigating across multiple pages.

The retrieval pipeline is fully benchmarked on 100 manually grounded questions, with BM25 selected after reaching 94% Hit@3. The finalized browser demo combines BM25 candidate retrieval, compact evidence selection, and Qwen3-0.6B for grounded local answer generation.

Final chatbot flow

From a visitor question to an evidence-backed answer.

01

User question

A visitor asks a natural-language question directly from the portfolio chatbot.

02

Local retrieval

The browser searches the prepared portfolio corpus and ranks the most relevant chunks.

03

Evidence selection

The strongest retrieved passages become the controlled context for answer generation.

04

Local generation

Qwen3-0.6B generates a concise answer from the selected evidence; verified extractive text is used if generation fails.

05

Source traceability

Retrieved passages retain source metadata internally for debugging and evaluation, while the visitor-facing page shows the exact text rather than internal identifiers.

Project completion

Implemented and validated stage by stage.

01 · Complete

Source curation

Selected the portfolio pages, RAG project pages, events, and publication summaries that should form the chatbot knowledge base.

02 · Complete

Corpus + chunking

Cleaned the source content and created heading-aware chunks with source, section, category, and traceability metadata.

03 · Complete

Offline embeddings

Embedded every chunk locally with Xenova/all-MiniLM-L6-v2 and stored the normalized 384-dimensional vectors as a compact static asset.

04 · Complete

Ground-truth benchmark

Created 100 manually grounded questions with graded relevance labels so retrieval can be measured independently from answer generation.

05 · Complete

Retrieval comparison

Compared Dense MiniLM, BM25, and equal-weight RRF, then inspected which questions and passages each method retrieved or missed.

06 · Complete

Website integration

The homepage presents the project summary, while the complete browser chatbot and technical retrieval analysis remain isolated on this dedicated project page.

07 · Implemented

Grounded generation

BM25 retrieves candidate chunks, the evidence selector keeps up to three compact supporting units, and Qwen3-0.6B rewrites only that controlled context. The model loads lazily on the first generation request and is warmed before producing the full answer.

08 · Future evaluation

Judge-based generation testing

Run the finalized pipeline over a fixed evaluation set and save each question, retrieved evidence, reference answer, Qwen answer, fallback status, and latency. Evaluate faithfulness/groundedness, factual correctness, answer relevance, and semantic similarity with an automated judge, compare with a stronger secondary judge where useful, and manually review a representative subset before reporting generation-quality results.

Remaining future task · detailed generation evaluation Retrieval evaluation is complete and BM25 is selected from the 100-question benchmark. The end-to-end generation path has been manually smoke-tested on several random questions and produces workable grounded answers. The remaining validation work is a formal judge-based generation study: run a fixed question set, preserve the retrieved evidence and reference answer for every case, score Qwen outputs for faithfulness/groundedness, factual correctness, answer relevance, and semantic similarity, compare judge behaviour where appropriate, and manually spot-check representative answers. Until that study is completed, this page intentionally reports no quantitative generation-quality score.

Demo architecture

BM25 retrieval + Qwen3-0.6B in the browser

The 88-chunk portfolio corpus is searched locally with the BM25 design selected by the retrieval benchmark. The runtime first ranks BM25 candidates, inspects the strongest five, then selects up to three compact evidence units before passing them to Qwen through Transformers.js and ONNX Runtime Web.
